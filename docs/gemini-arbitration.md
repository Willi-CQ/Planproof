# Gemini review of disputed door detections

The first V3 workflow compares door assemblies on one selected PDF page. Both engines work on the same raster. Python compares the door regions one by one. If the engines report a localized discrepancy, Gemini can inspect the original crop and return an advisory with evidence IDs. The API keeps the result at `NEEDS_REVIEW` after an advisory. A model opinion alone cannot establish the exact count or full-page coverage.

## Run the demo

From the repo root in the same Python environment used for the backend:

```powershell
python -m pip install -r backend/requirements.txt
python -m uvicorn app:app --app-dir backend --reload
```

Open [the API test page](http://127.0.0.1:8000/docs). Run **POST /api/v1/demo/door-count** with one of these scenarios:

| Scenario | Expected response |
| --- | --- |
| `agreement` | `SUPPORTED`, count 2, with matched boxes |
| `disputed` | `NEEDS_REVIEW`, with one disputed box |
| `missing_ml` | `INSUFFICIENT_EVIDENCE`, with ML marked unavailable |

These responses are labeled `synthetic_demo`. Both test detections are generated by the demo. The `image_url` opens its source page.

## Enable real Gemini review

Sign in to [Google AI Studio](https://aistudio.google.com/api-keys) with the event account and copy the API key from the assigned project. Use **Import project** if it is missing. Follow [Google's event account guide](https://goo.gle/hackathon-account).

From the repo root, run this command in PowerShell:

```powershell
python backend/check_gemini.py --serve
```

Paste the API key when prompted, then press Enter. The input is hidden and the key stays in the running process. The script sends one synthetic crop with `gemini-3.8-flash` by default. On success it opens the API on port 8001. Try **POST /api/v1/demo/door-count** with `scenario=disputed` and `allow_gemini_review=true` at [localhost:8001/docs](http://127.0.0.1:8001/docs). Omit `--serve` to run only the check. Set `GEMINI_MODEL` in PowerShell to use another available model.

For a regular uvicorn launch, set `GEMINI_API_KEY`, `GEMINI_MODEL` and `GEMINI_ENABLED=true` in the server environment. For uploaded drawings, enable review only when the source can be sent to Gemini.

The backend submits one original PNG crop, the two counts, the reason for review and the disputed candidate IDs. It skips review for more than eight disputed candidates or a crop covering more than half the page. The response includes an advisory, cited IDs and the bounds of the crop where available. Gemini failures preserve the local result and its evidence.

## Connect the engines

1. Upload a PDF and select a page using **POST /api/documents**. Save its `image_url` as `page.png`.
2. Save **GET /api/v1/documents/{document_id}/frame** as `frame.json`. The frame identifies the source PDF and the exact decoded RGB image. Page indexes start at zero. Boxes use pixel edges from the top left, ordered `[x0, y0, x1, y1]`.
3. Run Willi's documented `planproof-ml infer` command on that PNG, with the same `--page-index` and **without `--document-id`**. This makes the release record the input RGB hash. Convert the resulting `detections.json`:

   ```powershell
   python backend/ml_adapter.py detections.json frame.json
   ```

4. Post an object with the upload's `document_id`, the normalized result under `ml`, and the deterministic engine's result under `deterministic` to **POST /api/v1/door-count**. The fields can be inspected under `AnalyzerResult` in the API docs. The deterministic adapter should record the frame it actually processed, declare its version and mode, and return door IDs and boxes in the same coordinates. Omit an unavailable engine. Use `mode: "hybrid"` when the result depends on the other engine.

Only provide normalized outputs from trusted local engine runners. The API checks the reported frame against its registered page. The ML adapter checks the release's recorded raster hash and leaves coverage unknown. A count is supported only when both independent results report complete coverage and match one-to-one without ambiguous duplicates. The initial box overlap threshold is IoU 0.5. Tune it on real annotated drawings before relying on it.

## Verify locally

```powershell
python -m unittest discover -s backend -v
```

This runs against synthetic detections and mocks the Gemini transport. The trained detector and deterministic engine can be verified independently on the same canonical PNG before connecting their outputs.
